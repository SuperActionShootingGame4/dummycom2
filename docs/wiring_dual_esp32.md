# 2× ESP32-WROOM-32 構成 接続図(AUX 端子なし・デジタル直結案)

## 1. 全体構成

```
                                 (Bluetooth Classic HFP / SCO)
  ┌──────────────┐  メッシュ    ┌───────────────────────────┐
  │ SENA SRL3     │ ~~~~~~~~~~~~ │  ESP32 #1 (受信側 / "A")   │
  │ (Mesh 会話)   │  BT 無線     │  HFP-HF(ユニバーサル       │
  └──────────────┘              │  インターコム接続)          │
                                 │  SCO 音声受信 → 16kHz PCM   │
                                 └───────┬───────────────────┘
                                         │ ★有線 5 本(下記)
                                         │  I2S 3 本 + 5V + GND
                                         ▼
                                 ┌───────────────────────────┐        ┌────────────┐
                                 │  ESP32 #2 (送信側 / "B")   │ ~~~~~~ │ スマホ /    │
                                 │  HFP-HF (無線マイク役)      │ BT 無線│ Insta360 等 │
                                 │  I2S 受信 → SCO 送信        │        └────────────┘
                                 └───────────────────────────┘

  USB 5V ──▶ ESP32 #1 のみ(#2 の電源は #1 から分配)
```

- **AUX(3.5mm)端子・PCM5102A(DAC)・ADC・分圧回路はすべて不要**になります。
  音声はデジタル(I2S)のまま渡すので、AD/DA 変換によるノイズ・劣化もありません。
- #1 と #2 は Bluetooth コントローラを別々に持つので、Bluedroid の
  「1 起動 1 役」制約(`bt_role.h`)を回避できます。

## 2. 配線表

| 信号 | ESP32 #1 (A) | 向き | ESP32 #2 (B) | 備考 |
|---|---|:-:|---|---|
| I2S BCLK | GPIO26 | → | GPIO26 | #1 がマスタ(クロック供給) |
| I2S WS(LRCLK) | GPIO25 | → | GPIO25 | 〃 |
| I2S DATA | GPIO27 (DOUT) | → | GPIO27 (DIN) | モノラル 16bit(16kHz 推奨) |
| GND | GND | ─ | GND | **必須**(信号基準) |
| 電源 5V | VIN / 5V ピン | → | VIN / 5V ピン | 下記 §3 参照 |

- どちらも 3.3V ロジックなのでレベル変換不要。
- ノイズ対策として BCLK / WS / DATA に各 **33〜100Ω の直列抵抗**を入れると安心
  (配線 10cm 以内なら省略可)。
- 配線はできるだけ短く、GND 線を信号線と並走させてください。

### 各ユニットの LED / ボタン(従来どおり、別々に付ける)

| 部品 | GPIO | 接続 |
|---|---|---|
| LED PWR | 32 | LED + 1kΩ → GND |
| LED LINK | 33 | LED + 1kΩ → GND |
| LED SCO | 13 | LED + 1kΩ → GND |
| BOND-CLR ボタン | 14 | タクトスイッチ → GND(内部プルアップ) |

## 3. 電源(#1 から #2 へ供給)

```
   USB(5V)
     │
     ▼
 ┌────────────┐  VIN/5V ──────────────┬───────▶ #2 VIN/5V
 │ ESP32 #1    │                       │
 │ (devkit)    │  GND ─────────────────┼───────▶ #2 GND
 └────────────┘                     [100〜470µF] ← #2 側の VIN–GND 間に
                                       │            電解コンデンサ(BT 送信時の電流変動対策)
                                      GND
```

**推奨:5V ピン同士を接続**(3V3 ピン供給ではなく)
- #2 は自身のオンボードレギュレータ(3.3V)を使えるため、#1 の 3.3V に負荷が乗らず安定します。
- 消費電流の目安:BT 動作中 各 約 100〜250mA(ピーク)→ 合計 約 0.5A。
  USB 電源は **5V/1A 以上**を使用してください。

**3V3 ピンから供給する案(非推奨)**:#1 の 3V3 → #2 の 3V3 でも動作はしますが、
devkit の LDO(AMS1117 等)の余裕が小さく、BT 送信ピークで電圧が落ちて
切断・リセットの原因になり得ます。

### 注意
- **#2 に USB を挿したまま 5V 線を繋がない**(USB 電源同士の逆流防止)。
  #2 を書き込むときは 5V 線を外すか、#2 は書き込み時のみ USB、通常時は 5V 線、と使い分けてください。
- 裸モジュール(WROOM-32 単体)で作る場合は、5V→3.3V の LDO(AP2112K / AMS1117 で 600mA 以上)と
  EN・GPIO0 のプルアップ、書き込み用 UART ヘッダを各基板に付けてください。
- 2 つの ESP32 のアンテナは **できるだけ離す(5cm 以上)**、金属で覆わないこと。

## 4. ファームウェア変更点(概要・次段階)

| 項目 | #1 (A) | #2 (B) |
|---|---|---|
| 現行流用 | `main/`(HFP-HF 役 `BT_ROLE_HF`、SCO 受信、I2S 出力) | `hf_unit/`(HFP-HF、SCO 送信) |
| 変更 | I2S 出力を 16kHz モノに(PCM5102A 用 48kHz アップサンプルを省略) | `adc_capture.c` を **I2S スレーブ受信**に置換 |
| 削除 | PCM5102A 依存 | ADC / DC バイアス処理 |

## 5. 確認したい点

1. スマホ側 = マイク用途の接続先は Insta360 X4 のままか、一般のスマホか(HFP マイク接続になります)。
2. #1 は SRL3 ユニバーサルインターコムの HF 役で問題ないか(現行 `BT_ROLE_HF` 検証中の状態)。
3. 基板は devkit 使用か、裸モジュールか(§3 の電源設計が変わります)。
