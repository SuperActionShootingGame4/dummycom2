# Dummy Intercom HF ユニット — アナログ音声 → Bluetooth マイク(Insta360 X4 向け)

AG ユニット(本リポジトリ直下)のアナログ出力を**直接配線**で取り込み、ESP32 の ADC で
サンプリングして **HFP Hands-Free(HF)ロール**(`esp_hf_client`)で **Insta360 X4** に
Bluetooth マイクとして接続する、2 台目 ESP32-WROOM-32 用ファームウェアです。
X4 側の録画機能で SRL-3 インターコムの音声を録音することが目的です。

音声はアップリンクのみ(HF ユニット→X4、マイク方向)です。X4→HF ユニットの
ダウンリンク音声は受信自体を破棄します(本機に再生ハードウェアはありません)。
発着信の実処理・通話偽装はありません(HFP クライアント役には CIND/CLCC/COPS
等への応答 API 自体が存在しないため。設計書 §13.0 H-D)。

> **仕様 rev 0.9 / 設計書 §13(rev 0.8a)対応。実機(ESP32 ×2 + Insta360 X4)は
> 本開発環境に無く、ビルド + 静的検証まで実施・実機動作は未検証です**
> (`dummy_intercom_spec.md` §12 R12〜R16、設計書 §13.9 参照)。
>
> **rev 0.9 でのハードウェア変更**: AG ユニットの 3.5mm AUX 出力(旧 J1、外部レコーダー/
> カメラ向け)は完全に廃止されました。AG ユニットの出力は本ユニットへの**直接配線**
> 専用となり、外部機器への分岐・並列出力はありません。ファームウェア(本プロジェクト)
> 自体に変更はありません — 変わったのは物理的な接続方法のみです。

- ターゲット: `esp32`(オリジナル ESP32、BR/EDR Classic 必須)
- SDK: ESP-IDF v5.4、Bluedroid ホスト
- 本プロジェクトは**リポジトリ直下の AG ユニット(`main/` 以下)とは完全に独立した
  ESP-IDF プロジェクト**です。ファイルの共有・相互参照は一切ありません。

## ビルド

```sh
export IDF_TOOLS_PATH=/home/subcon/.espressif
. /home/subcon/esp/esp-idf/export.sh
cd /home/subcon/SOURCE_CODE/dummycom
idf.py -C hf_unit set-target esp32
idf.py -C hf_unit build
idf.py -C hf_unit -p /dev/ttyUSB0 flash monitor
```

`sdkconfig.defaults` は公式 `examples/bluetooth/bluedroid/classic_bt/hfp_hf/sdkconfig.ci.vohci`
(Voice-over-HCI、HFP クライアント役)をベースに、AG ユニットと同様の追加設定
(WBS 有効化、`BT_HFP_AG_ENABLE=n` で AG 機能を省いて Flash 節約、カスタム
パーティションテーブル)を加えたものです。詳細は設計書 §13.5.1 を参照してください。

AG ユニット(リポジトリ直下)は本プロジェクトの追加によって一切変更されません。
`idf.py build`(リポジトリ直下)は従来どおり独立してビルドできます。

## 配線

| 信号            | ESP32 GPIO | 接続先                                      |
|-----------------|-----------:|---------------------------------------------|
| ADC 音声入力    | 34         | 分圧/バイアス回路経由で AG ユニットの DAC 出力と直接配線(下記参照) |
| LED PWR         | 32         | LED + 1 kΩ → GND(起動 OK)                  |
| LED LINK        | 33         | LED + 1 kΩ → GND(ACL/SLC)                  |
| LED SCO         | 13         | LED + 1 kΩ → GND(音声送出中)                |
| BOND-CLR ボタン | 14         | タクトスイッチ → GND(内部プルアップ)         |

LED/ボタンの GPIO 番号は AG ユニットと同一ですが、**別基板・別電源**なので
物理的な衝突はありません。

### ADC 入力ピンについて(GPIO34、rev 0.8b で確定)

仕様書の旧版は AG ユニットの I2S 用ピン(GPIO25/26/27)を ADC 用途に読み替える
想定でしたが、これらは **ADC2** チャンネルであり、ESP32 の連続サンプリング
(DMA)ドライバ `adc_continuous` は ADC2 をサポートしません
(`adc_continuous.c` に明記されたハードウェア制約)。そのため本設計は
**GPIO34(ADC1_CHANNEL_6、入力専用ピン)を正式採用**しています。

**配線前に、使用する実基板(Wemos/LOLIN ESP32 mini 相当)で GPIO34 がヘッダに
実際に露出していることを確認してください**(設計書 §13.9 U-H02)。露出していない
場合は `hf_unit/main/app_config.h` の `PIN_ADC_AUDIO_IN` と `ADC_CHANNEL_USED` を
他の ADC1 ピン(GPIO35=CH7、GPIO36=CH0、GPIO39=CH3 など)に差し替えてください。

### 入力段(分圧 + DC バイアス + アンチエイリアスフィルタ)の設計目安

**以下の抵抗・容量値はベンチで実測しながら追い込むための「たたき台」の見積もりで
あり、精密設計ではありません**(仕様書 §4.5 には出力レベル 0.3–1.0 Vrms 固定という
想定値しかなく、具体的な抵抗値の指定はありません)。AG ユニットの出力段(§4.4、
rev 0.9 で 3.5mm ジャックは廃止され、本ユニットへの直接配線のみになっています)と
同様に、実機でオシロスコープ/ロジックアナライザを見ながらトリムしてください。

```
AG ユニット DAC 出力(0.3–1.0 Vrms 固定, 出力インピーダンス < 300Ω, 直接配線・分岐なし)
        │
      [Cin 1µF]  (DC カット。AG側の出力にDC成分はほぼ無い想定だが念のため)
        │
      [Rin 47kΩ]
        │
        ├──────────────── ESP32 GPIO34 (ADC1_CHANNEL_6)
        │                         │
  3V3 ─[R1 100kΩ]─┤          [Cf 470pF]  (アンチエイリアス、対GND)
        │                         │
  GND ─[R2 100kΩ]─┘              GND
```

- **バイアス**: `R1 = R2 = 100kΩ` で ADC ピンを VDD/2 ≈ 1.65V にバイアスする
  (ESP32 の ADC は単電源・0–3.3V しか扱えないため、交流信号を直流バイアスに
  乗せる必要がある)。Thevenin 抵抗は `R1 // R2 = 50kΩ`
- **減衰**: `Rin = 47kΩ` を直列に入れることで、交流的には
  `R1//R2 / (Rin + R1//R2) = 50k / 97k ≈ 0.52` 倍に減衰する。
  LINE レベル最大値 1.0 Vrms(ピーク ≈1.41V)に対して 0.52 倍 ≈0.73Vpk となり、
  1.65V バイアスを中心に約 0.92–2.38V の範囲に収まる(ESP32 ADC の
  `ADC_ATTEN_DB_12` 設定でのフルスケール 0–3.3V に対して十分なマージンを残す)。
  MIC レベル(3–30mVrms)を直接入力する場合はこの減衰は不要なので `Rin` を
  数百Ω程度まで下げる、または省略する
- **DC カット**: `Cin = 1µF`。`Rin + (R1//R2)` との時定数から低域カットオフは
  約 1.6Hz(可聴帯域に影響しない)
- **アンチエイリアスフィルタ**: `Cf = 470pF` を ADC ピン~GND 間に入れ、
  ノードのインピーダンス(`R1 // R2 // (Rin + AG出力インピーダンス)` ≈ 24kΩ)との
  組み合わせでカットオフ ≈14kHz の 1 次ローパスを形成する。ADC は固定 32kHz で
  サンプリングする設計(設計書 §13.0 H-A)なので、ナイキスト周波数 16kHz に対して
  マージンを残しつつ、mSBC(帯域 ~7kHz)にも大きな影響が出ない値を狙った目安。
  CVSD 運用主体で高域が不要なら `Cf` を大きくして(例: 1nF、カットオフ ≈6.5kHz)
  エイリアス耐性を上げてもよい
- **ADC のソースインピーダンス**: ESP-IDF は ADC1 の入力ソースインピーダンスを
  低め(目安 <10kΩ)に保つことを推奨しています。本回路のノードインピーダンス
  (約24kΩ)はこれより高いため、実測でノイズ/非直線性が気になる場合は
  ボルテージフォロワ(オペアンプ 1 個、例: MCP6001 等)を `Rin`〜ADC ピン間に
  挟んでバッファすることを検討してください(ファームウェア側は 4 サンプル
  平均のボックスカー間引きを行っているため、多少のノイズはある程度平均化
  されます)
- **絶縁**: AG ユニットと HF ユニットは別電源です。直接配線する場合は
  グラウンドループに注意してください(仕様書 R14)。ノイズが問題になる場合は
  AG ユニットの出力段(§4.4)と同様に 1:1 オーディオトランスでの絶縁を検討して
  ください

## I2S スレーブ入力(CR-012)

`main/app_config.h` の `AUDIO_IN_MODE` で音声入力を切り替えます(コンパイル時)。

- `AUDIO_IN_I2S`(既定)= 1 台目 ESP32(`main/`)からの 16 kHz / 16 bit / モノ / Philips / 左スロットを I2S **スレーブ**で受信します(BCLK=GPIO26、WS=GPIO25、DIN=GPIO27)。SCO が CVSD(8 kHz)のときは本機で 8 kHz へ間引き、クロック差は 1 サンプル単位の挿入/削除で吸収します。短い入力不足は無音で埋めて送信します(上限 200 ms)。
- `AUDIO_IN_ADC` = 従来の ADC1(GPIO34)入力。**アナログ入力構成に戻すにはこの値に変更して再ビルドします**(下記の ADC 節は `AUDIO_IN_ADC` 時のみ有効)。

配線: 1 台目と I2S 3 本 + GND 共通 + 5 V(1 台目から供給)。詳細は `docs/wiring_dual_esp32.md`。

## LED の状態

| LED  | 消灯            | 点滅                       | 点灯               |
|------|-----------------|----------------------------|--------------------|
| PWR  | —               | 5 Hz = BT 起動失敗          | 起動完了           |
| LINK | 未接続          | 1 Hz = ページング/再接続中  | ACL/SLC 確立済み   |
| SCO  | 音声リンクなし  | 約 10 Hz = バッファ異常     | SCO 確立中(送出中) |

## 初回ペアリング

1. 基板を書き込んで電源を入れます。`DummyIntercomMic` は最初のボンドが完了するまで検出可能な状態です。
2. Insta360 X4 側で Bluetooth マイク(DJI Mic 等と同様の外部マイク)登録操作を行い、`DummyIntercomMic` を選択します(PIN なし、Just Works 暫定・§13.9 U-H04)。
3. シリアルログに `SLC connected` が表示され、相手の BDA が NVS に書き込まれます。続けて自動的に SCO 接続を試みます(`SCO connected` ログ)。
4. 以降、基板は非検出状態となり、その相手へ自動再接続します。

**BOND-CLR(GPIO14)を 3 秒間長押し**すると、ボンドと保存済みの相手情報が消去され再起動します。

> X4 が本機を HFP-HF マイクとして実際に受理するか(CoD・ペアリング方式・
> SCO 許可挙動)は実機未検証です。うまくいかない場合はまず
> `main/app_config.h` の `BT_COD_MINOR_MICROPHONE` を Headset(0x01)や
> Hands-free(0x02)に変更して試してください(設計書 §13.9 U-H01)。

## 動作に関する補足

- **SCO キープアライブ**: SLC が確立している間、HF ユニットは `connect_audio` を
  3 秒ごとに再試行し、SCO が維持されるようにします(AG ユニットの同名機構と
  対称。設計書 §13.5.7)。X4 が「通話中でないと SCO を許可しない」実装だと
  常時 SCO 維持が成立しない可能性があります(設計書 R-HF-06、実機確認が必要)。
- **再接続**: ACL が切断されると、保存済みの相手に対して 5 秒ごとに
  `connect`(SLC 接続)を呼び出します。
- **ADC → SCO のデータフロー**: ADC1 を固定 32kHz でオーバーサンプルし、
  ソフトウェアでボックスカー平均による間引き(CVSD時 ÷4=8kHz、mSBC時 ÷2=16kHz)
  + 1 次 DC ブロッカを適用したのち、送信用リングバッファ(`TX_RB_BYTES` 4096
  バイト)へ書き込みます。送信コールバックはプリフィル(`TX_PREFILL_BYTES`
  480 バイト = 30ms@8kHz)未達、またはリングバッファ不足時は **0 を返して
  送信をスキップ**します(ゼロ埋め送信はしない。設計書 §13.5.6、RQ-H05)。
- **コーデック**: WBS が有効なため、X4 が mSBC を要求すれば追従します
  (`ESP_HF_CLIENT_AUDIO_STATE_CONNECTED_MSBC` で ADC の間引き係数を自動的に
  ÷2 へ切替)。CVSD 固定に戻したい場合は `sdkconfig` の `BT_HFP_WBS_ENABLE=n`
  と `main/app_config.h` の間引き係数を確認してください。
- **ダウンリンク(X4→HF ユニット)は完全に無視**します。本機に再生ハードウェアは
  無く、`recv_cb` は引数を使わず即 return する no-op です(設計書 §13.0 H-D)。
- **通話制御 API は一切使用しません**(`answer_call`/`dial`/`send_dtmf` 等)。
  本機能はマイク専用であり、HFP クライアント役には CIND/CLCC/COPS 等への
  応答 API 自体が存在しません。

## ハードウェアスモークテスト(ESP32 ×2 + Insta360 X4 実機が必要 — 本リポジトリ内では未実施)

| # | 手順 | 合格基準 |
|---|------|----------|
| T14 | Insta360 X4 とのペアリング(最優先・最大の不確実性) | PIN なし/確認プロンプトで `SLC connected` がログに出る、NVS に保存される |
| T15 | X4 の録画を開始し、AG ユニット側で音声を再生 | X4 の録画に音声が記録される。CVSD/mSBC いずれかでログにコーデックが出る |
| T16 | 録画された音声の品質確認 | 聞き取れる品質であること。不十分ならボックスカー間引きを真の FIR デシメーションに置き換える(設計書 R-HF-04) |
| T17 | エンドツーエンド遅延の実測 | 設計書 §13.7.3 の見積り(追加約60ms、AG ユニット単体と合わせ約150–170ms)と照合 |

**T14(ペアリング)は本プロジェクトにおいて最も大きな未検証項目です** —
ビルドと静的レビューは完了していますが、実機(ハードウェアなし)での X4 との
実際のペアリング・SCO 音声のやり取りは検証されていません。
